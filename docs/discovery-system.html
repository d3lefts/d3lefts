NIGHTFALL is organized around a simple constraint: a mathematical claim is not more credible than the evidence, assumptions and independent criticism attached to it. Preserve the representation that made the idea possible, the mechanism that worked, the certificate that can be replayed, and the conditions under which the idea might transfer.

01 / A RESEARCH CYCLE

One discovery.
A complete trail.

Each stage produces a different kind of object. Later stages never silently erase the limits of earlier ones.

  1. 01 / REPRESENT

    State the problem.

    Define the domain, assumptions, symmetry, observables and the cheapest test that could fail.

    Output / exact statement & feasible set
  2. 02 / INVENT

    Identify the mechanism.

    Use matching, two-draw symmetry, exact arithmetic or another explicit operator—not an unsupported analogy.

    Output / construction or hypothesis
  3. 03 / CERTIFY

    Attach a passport.

    Keep validity, reproducibility, originality and significance separate; link source files, checkers and dependencies.

    Output / scoped claim & evidence
  4. 04 / ATTACK

    Try to break it.

    Reproduce the inputs, challenge proof assumptions, seek counterexamples and request outside mathematical review.

    Output / independent audit obligations
  5. 05 / REMEMBER

    Preserve what changed.

    Retain corrections, adverse results, superseded candidates, source attribution and the precise reason for any status change.

    Output / versioned research history
  6. 06 / TRANSFER

    Connect cautiously.

    Link problems through a typed mechanism; prove new scope conditions before claiming that a result transfers.

    Output / sourced relationship, not proof by proximity

04 / PUBLICATION BOUNDARY

A certificate travels
only as far as it proves.

Numerical replay is not a global bound. Kernel compilation certifies only the exact formal declaration and its imported assumptions. Internal cross-model criticism is not an independent human referee. Novelty requires a dated, scope-matched prior-art review. A failed experiment stays in the record; no status automatically upgrades when a page, workflow or graph renders successfully.
