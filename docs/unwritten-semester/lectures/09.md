## The operating principle

**Verification** tests conformance to a specified model or requirement. **Validation** asks whether the model or requirement is right for the stakeholder's actual need. **Assurance** makes the argument that evidence is adequate for a particular consequential decision. They are connected but not synonyms.

A passing test is a fact about a test run. It becomes assurance evidence only after you know its purpose, scope, source version, assumptions, coverage, and limitations. Strong assurance cases also identify defeaters: observations that invalidate the argument.

## Claim → argument → evidence

Use a compact assurance case:

- **Top claim:** the trace report correctly represents AURORA policy outcomes for the archived synthetic run.
- **Argument:** the generator records primitive episode variables; decision policy is specified; a separate checker recomputes the decision from the trace.
- **Evidence:** source hash, command, seed, CSV, audit result, test suite.
- **Assumptions:** the language runtime and file bytes behave as declared; input data are complete and unmodified.
- **Limits:** no claim about physical sensors or field safety; the audit program is not a formal proof and does not independently validate the generator's statistical model.

An evidence passport makes a claim travel with the minimum facts needed to understand what it certifies, without confusing provenance with truth.

## Lab — build and challenge a passport

1. Run the simulator and the auditor with the commands in `README.md`.
2. Create a file listing claim ID, scope, source/version hash, checker command, result, dependencies, and known exceptions.
3. Deliberately edit one alarm bit in the CSV and rerun the auditor. Confirm that it fails.
4. Deliberately change a **model assumption** while leaving the policy checker untouched. Explain why the checker can still pass although the real-world interpretation is different.
5. State who has authority to accept the evidence and what would trigger revalidation.

**Acceptance artifact:** `09-assurance-passport.md` with a verified computation claim and a conspicuous unverified modeling claim.

## Adversarial check

Separate three questions: Does the file hash match? Does the checker validate the promised property? Does the property answer the mission question? A hash can prove byte identity relative to a trusted digest; it cannot prove correctness.

## Doctoral extension

Choose one result suitable for a machine-checkable formal specification. Encode the decision rule in a second language, or a proof assistant, and prove a refinement statement relating the abstract rule to the executable behavior. State unverified compiler and runtime assumptions.
