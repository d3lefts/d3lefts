01 / REALISTIC ENGINEERING CONTRACT

Make the system correct,
not just the tests green.

The task is not a single-function toy. Errors can be exposed by time passing, workers racing, retries exhausting, duplicate submissions or reopening the database in another process.

DURABLE IDENTITY

Submit once.

Repeating an ID, even with changed payload or due date, must not overwrite existing state. A reopened process must see the same persisted record.

State transitions
CONCURRENT OWNERSHIP

Claim once.

Independent processes must claim atomically under SQLite locking, honor due-time order and never yield the same live job to simultaneous workers.

Interleaving and ordering
TIME AND FENCING

Finish only if current.

Expired or stale lease tokens must never authorize a finish or retry. Attempts are bounded, terminal states remain terminal, and exhausted jobs dead-letter.

Construction meets
independent attack.

The same question has two distinct workflows. The construction engine creates a task, a deliberately defective starter, a reference and a proposed grader. STEP 04 / ADVERSARIAL

Try alternate correct solutions.

An independent implementation must pass an audited grader. Plausible shortcut solutions and mutation families must fail for the right reason, without depending on private source signatures. This is an outstanding gate.

Execute genuine coding agents.

Run blind copies with normal tools, preregistered inference and time budgets, source-pinned evaluators, complete tool traces and independent isolated grading. A failed tool-call protocol is a failed evaluation setup, not agent success or defense success.

03 / WHY THIS TEST CAN BE DISCRIMINATING

Passing the happy path
is a weak signal.

Failure anatomy

Documented mechanisms, not model scores
Duplicate submission silently destroys state

The defective starter uses a replace-on-conflict write. Submitting the same ID with a later due time mutates the original record, despite returning a duplicate indication. A good grader checks row identity and full state after rejection, not only the return value.

Time-of-check / time-of-use race across processes

The starter lists eligible jobs before a separate transaction marks them leased. Two processes can observe the same row before either obtains exclusive ownership. A correct repair needs transactional claiming under SQLite semantics; an in-process mutex is insufficient.

Stale worker can acknowledge after expiry

The starter's finish updates on job ID and token but omits unexpired lease-state requirements, enabling a completion even after a lease has expired. Token fencing must hold across retries and all terminal transitions.

Deadline and attempt exhaustion are separate invariants

Claims must order by due time before insertion time and ID, while expired exhausted leases should become dead. A patch that fixes ordering but ignores lifecycle termination is incomplete.

Submission input and clock validation

NaN, infinities, invalid payload types, empty worker IDs and nonpositive lease settings can compromise invariants. The public probe treats these as separate semantic obligations, not incidental database exceptions.
